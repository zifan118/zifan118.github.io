Harborly

Individual project · 2025

The question

Can a community platform be designed so that being seen feels less like being judged?

Module
COMM2754 Programming for Digital Media, University of Leeds
Format
Individual project: full-stack community website and written rationale
My role
Concept, research framing, interface design and all code
Built with
PHP, MySQL, sessions, password hashing, reCAPTCHA, HTML, CSS, JavaScript

Why build it

Social anxiety is usually treated as an individual problem. Harborly starts from the idea that platforms shape it too: likes, rankings and comparison turn expression into competition, and for people who fear negative evaluation, being seen itself becomes the source of stress.

The site treats stories, tags and anonymous comments as the core data, rather than metrics, and tries to make a lower-pressure space to share them.

Drawing on data activism (Schrock, 2016) and van Dijck, Poell and de Waal’s platform society.

Design decisions · five stops

  1. 01

    Narrative over metrics

    No leaderboard, no “most popular”, no celebrity accounts. Likes stay as a quiet signal of support, not a ranking.

  2. 02

    Control of exposure

    Every post and reply can be anonymous or named, so users decide how visible they are.

  3. 03

    No likes on comments

    Replies are deliberately not scored, so speaking up is not judged.

  4. 04

    Gentle visual language

    Low-saturation lavender, rounded forms and storytelling layouts instead of clinical charts or dials.

  5. 05

    A right to delete

    Users can remove their posts or their whole account: expression need not be a permanent record.

Code as care

Because the site handles sensitive personal narratives, the technical choices were framed as ethical ones.

Passwords
Stored only as hashes
Queries
Prepared statements against SQL injection
Sign-up
Server-side reCAPTCHA on registration
Pages
Session check at the top of every protected page
Input
Sanitised throughout

About this copy

GitHub Pages cannot run PHP, so each page was rendered from the original code against a local database of sample posts and saved as HTML. Searching, sorting and likes work in your browser; posting, commenting and sign-up show a notice instead of saving.
