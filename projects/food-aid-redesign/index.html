Food Aid Redesign

Interface design · 2025

Leeds Food Aid Network

When someone needs emergency food, how many clicks should it take to find it?

Module
COMM1730 Interface Design, University of Leeds
Format
Evaluation report, user testing and a five-page redesign
My role
Individual project: research, evaluation, design and code
Methods
Heuristic evaluation, task-based user tests, WCAG and W3C audits

The evaluation

Leeds Food Aid Network coordinates food banks, food parcels and support across the city. Its website serves three very different people: someone looking for help, a donor, and a volunteer.

I evaluated it with Nielsen’s heuristics and Krug’s five-second and trunk tests, ran task-based tests with users from each group, and audited the code against WCAG 2.1 and the W3C validators.

Person 1Seeking help

Needs the nearest food bank, fast.

Person 2Donor

Wants to offer food or items.

Person 3Volunteer

Wants to know how to join in.

What I found

  1. Finding 01

    Navigation

    The main menu was hidden behind an icon and unreachable by keyboard, and labels like “Resource Centre” hid the donation route. Testers described the first impression as “messy”.

  2. Finding 02

    Trust

    Dropped into a deep page, users could not tell whose site it was or what it was for.

  3. Finding 03

    Accessibility

    Images without alt text, low-contrast text, no skip link, and a map that keyboard and screen-reader users could not operate.

  4. Finding 04

    Code

    Duplicate IDs, unclosed and invalidly nested tags, and a map layout whose icons overlapped at smaller widths.

The redesign

Five pages, each answering one of the problems above.

Get Food
One page, four clear sections
Donor
A short form instead of a long statement
Vouchers
Plain-language eligibility
Contact
One place for every way to get in touch

How it’s built

A persistent top navigation with plain labels and a skip link, hand-coded in HTML, CSS and JavaScript.
